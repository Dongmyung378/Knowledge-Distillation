# 실험 과정, 설계 선택 이유 및 트러블슈팅

각 해상도, 교사·학생 백본, 증류 손실, 양자화 게이트, 강건성 학습, 사후 보정 기법을 **어떤 실험 가설로 검증해 선택했고, 어떤 대안을 어떤 수치 근거로 기각했는지**를 시간순 실험 과정에 따라 정리한 문서입니다.

## 1. 평가 프로토콜 및 환경 설계 판단

| 설계 결정 | 선택 이유 | 기각한 대안 |
| :--- | :--- | :--- |

| **3분할 + SHA-256 평가 동결 (`evaluation-freeze`)** | Cityscapes 2,975장 학습셋을 `train 2,529 / validation 446`으로 분리하고 공식 500장 검증셋을 `locked_eval`로 격리했습니다. 모델 선택·INT8 게이트·온도 보정 `T*`는 모두 `validation` 전용으로 고정하고, 체크포인트·ONNX SHA-256을 동결한 뒤 `locked_eval`을 단 1회 평가했습니다. | `locked_eval` 점수를 보고 하이퍼파라미터·INT8 통과 여부를 재조정하는 방식. |
| **공유 초기 가중치 기반 3시드 쌍체 검증 (`378, 379, 380`)** | 단일 시드에서 `+0.5~1.0%p` 차이는 초기화 운일 수 있습니다. `baseline`과 `cwd_feat`가 정확히 같은 초기 체크포인트(`weights_sha256` 일치)에서 출발하도록 통제해 증류 효과만 순수하게 분리했습니다. | 서로 다른 초기화의 단일 시드 비교. |
| **교차 데이터셋 KITTI Semantics Zero-Shot (`200장`)** | Cityscapes 단일 카메라·독일 도심 환경 과적합 여부를 확인하기 위해 미세조정 0회로 타 센서·타 도로(KITTI) 일반화 성능을 검증했습니다. | 동일 데이터셋 내 정확도만 보고. |

| :--- | :--- | :--- | :--- |

| **Stage 2. `384×768` 4종 손실 소거** (`1.50M`, `s378`) | 픽셀 KL, 공간 CWD, 4단계 특징 정렬 중 무엇이 이종 ViT→CNN 압축에 유효한가? | `baseline` `61.65%` → `pixel_kl` **`59.25%` (`-2.41%p`, Safety `-5.71%p`)** → **`cwd` `63.07%` (`+1.42%p`, KITTI Safety `+7.12%p`)** → `cwd_feat` `62.00%` | **`pixel_kl` 기각**, 공간 `CWD`를 핵심 증류 손실로 채택. |
| **Stage 3. 3시드 쌍체 검증** (`1.50M`, `378/379/380`) | 증류 이득이 시드 운 없이 재현되며 안전 핵심 6종이 고르게 오르는가? | `61.42% ± 0.21%` → **`62.03% ± 0.08%`** (`+0.61%p`, **3/3 승**, SD `2.7×` 축소), Safety `49.52%` → **`51.40%`** (`+1.88%p`, **6/6 전원 상승**) | 증류의 안전 클래스 향상 및 분산 안정화 입증. |

| **Stage 6. 사후 온도 보정 (`ECE`)** | CWD 증류 모델의 신뢰도 과신(`ECE 0.025~0.031`)을 정확도·속도 손실 없이 줄일 수 있는가? | `validation` NLL 최적화 시 모든 CWD 모델이 `T* = 1.70~1.72`로 수렴 → **`locked_eval` ECE `-69.5~78.5%` 감소**, mIoU 변화 `0.00%p`, 지연 `0 ms` | 단일 스칼라 `T*` 온도 보정을 표준 추론 후처리로 채택. |

## 3. 핵심 설계 선택 이유 상세 분석

### 3.1 왜 표준 `Pixel KL`을 기각하고 `CWD`를 선택했는가?
도로 장면은 도로·건물·하늘·식생이 전체 픽셀의 대부분을 차지하고, 신호등(`traffic_light`), 표지판(`traffic_sign`), 보행자(`person`), 자전거(`bicycle`)는 면적이 극도로 작습니다. 픽셀별 Softmax KL(`pixel_kl`)은 각 픽셀의 19클래스 분포를 맞추려 하므로 그래디언트가 배경 다수 클래스에 압도되고, `56×` 용량 격차(`84.6M → 1.50M`)에서 소수 안전 클래스를 무너뜨립니다(`locked_eval -2.41%p`, Safety `-5.71%p`).

반면 **Channel-Wise Spatial Distillation**(`CWD`)은 각 클래스 채널 내부에서 공간 좌표 `(H×W)`에 대해 Softmax를 취합니다. 따라서 신호등 채널과 도로 채널이 동일한 공간 가중치를 받아, 작은 안전 객체의 위치·경계 지식이 왜곡 없이 학생에게 전달됩니다(`63.07%`, `+1.42%p`, KITTI Safety `+7.12%p`).

또한 `1.50M`(`56×` 극한 압축)에서는 4단계 중간 특징을 강제 정렬하는 `cwd_feat`(`62.00%`)보다 공간 로짓만 정렬하는 `cwd`(`63.07%`)가 더 높았으나, 수용력이 충분한 `7.54M` `MobileNetV4-Medium`(`11.2×` 압축)에서는 `cwd_feat`가 `68.51%`(FP32) / `67.95%`(INT8)로 무교사 기준선(`67.15%`)과 KITTI Zero-Shot(`51.32%`, Safety `+7.46%p`)을 크게 앞섰습니다. 즉, **압축 배율에 따라 중간 특징 제약 강도를 다르게 봐야 한다는 구조적 발견**을 얻었습니다.

### 3.2 왜 `MobileNetV3-Large`를 기각하고 `MobileNetV4-Medium`을 채택했는가?
배포 모델은 FP32 정확도뿐 아니라 **정적 QDQ INT8에서 정확도 하락 `1.0%p` 이내, CPU `1.2×` 이상 가속**을 동시에 만족해야 합니다.
- **`MobileNetV3-Large` (`3.30M`, `74 Conv / 56 BN`)**: 18개의 비융합 Squeeze-and-Excitation(SE) 곱셈 분기와 비대칭 HardSwish 활성화가 정적 INT8 캘리브레이션 범위를 깨뜨리고, CPU 그래프에 빈번한 Quantize/Dequantize 전환을 삽입했습니다. 그 결과 검증 mIoU가 **`-6.46%p`** 붕괴하고 속도는 오히려 **`0.72×`** 느려져(`24.24 ms → 33.18 ms`) 게이트에서 자동 차단되었습니다.
- **`MobileNetV4-Small` (`1.50M`, `57 Conv / 55 BN`)**: 정확도 하락은 `0.55%p`로 양호했지만, 원래 연산량이 워낙 작아 QDQ 오버헤드 대비 CPU 가속이 **`1.04×`**(`16.77 ms → 15.85 ms`)에 그쳐 `1.20×` 게이트 기준에 미달했습니다.
- **`MobileNetV4-Medium` (`7.54M`, `88 Conv / 86 BN`)**: 순수 `Conv-BN-ReLU` UIB 블록 구조 덕분에 연산 융합이 깔끔하게 이루어져, `v3-max`와 `v4-final` 모두 **파일 크기 `-72.5%` (`28.71 → 7.90 MiB`), CPU `1.55×` 가속 (`38.1 → 24.7 ms`, `40.5 FPS`), 검증 mIoU 하락 `0.64~0.95%p` 이내**로 4/4 조건을 통과했습니다.

### 3.3 왜 일반 증강 대신 비대칭 강건성 증류(`v4-final`)를 선택했는가?
`v3-max` 스트레스 테스트에서 깨끗한 이미지만으로 증류한 `Clean INT8`이 가우시안 노이즈(`σ=18`)에서 `13.75%`로 붕괴하는 치명적 약점을 발견했습니다.
만약 교사와 학생 모두에게 열화 이미지를 보여 주면, 교사 자신도 노이즈에서 `59.19%`로 흔들린 부정확한 타깃을 학생에게 가르치게 됩니다. 대신 **교사는 항상 열화 전 깨끗한 원본 이미지를 보고, 학생에게만 5에포크 램프 스케줄(`p: 0.07 → 0.35`)로 야간·모션 블러·안개·노이즈를 주입**했습니다.

이 비대칭 구조는 학생에게 "노이즈가 낀 입력에서도 깨끗한 장면의 4단계 특징과 로짓을 복원하라"는 디노이징 표현 학습을 강제하며, 결과적으로 **`7.90 MiB` INT8 학생이 `σ=18` 노이즈에서 `59.59%`(FP32 `60.61%`)를 달성해 `84.6M` 교사(`59.19%`)를 추월**하는 성과를 냈습니다.

### 3.4 왜 사후 온도 보정(`Validation-Only Temperature Scaling`)을 선택했는가?
CWD의 `T=4.0` 공간 정규화로 학습된 학생은 정확도는 높지만 로짓 크기가 과도하게 커져 `locked_eval` ECE가 무교사 기준선(`0.0146~0.0151`) 대비 약 2배(`0.0253~0.0305`)로 나빠졌습니다. 자율주행 인지 시스템에서 과신된 오탐은 경로 계획 실패로 직결됩니다.
`validation` 분할에서만 NLL을 최소화하는 단일 스칼라 온도 `T*`를 추정한 결과, 모든 CWD 모델이 아키텍처·양자화 여부와 무관하게 `T* = 1.70~1.72`로 수렴했으며, 추론 시 로짓을 `T*`로 나누는 연산(`0 ms`, `argmax` 수학적 불변 → mIoU 변화 `0.00%p`)만으로 `locked_eval` ECE를 **69.5~78.5% 감소**시켰습니다(`v4 Robust INT8: 0.0260 → 0.0067`).

## 4. 구현 과정의 주요 트러블슈팅

1. **초기 `cwd_safety` 클래스 가중 CE 과보정 문제**: 소수 안전 클래스에 고정 CE 가중치를 과도하게 부여했을 때 배경 오분류(false positive)가 늘어 전체 mIoU가 하락했습니다. CE는 무가중(unweighted)으로 유지하고 소수 클래스 강화는 `CWD` 공간 정규화가 담당하도록 분리해 6/6 안전 클래스 상승과 전체 mIoU 개선을 동시에 달성했습니다.
2. **QAT-KD 학습 속도 및 `channels_last` 호환성**: PyTorch QAT 중 `FakeQuantize` 그래프와 `channels_last` 메모리 포맷 충돌 위험을 제거하기 위해 `cfg.get("channels_last", False)` 안전 분기를 적용하고, 동결된 `SegFormer-B5` 교사 추론만 `torch.amp.autocast("cuda", dtype=torch.bfloat16)`으로 가속해 QAT-KD 6에포크를 에포크당 ~148초로 안정화했습니다.
3. **ONNX FP32 수치 일치 검증 (`100.0%` argmax parity)**: `EdgeSegStudent` 내보내기 시 학습 전용 프로젝터와 딕셔너리 반환 경로를 `_PlainLogitsExportWrapper`로 분리하고, 모든 내보내기 모델에 대해 PyTorch vs ONNXRuntime 픽셀 argmax 일치율 `100.0%`(`max_abs_logit_diff <= 3.6e-5`)를 자동 검증했습니다.
